# FastWY

Консольный прототип поиска статистически значимых подгрупп. Использует правосторонний точный тест Фишера и одношаговую перестановочную поправку Westfall–Young minP при α = 0,05.

## Сборка и запуск

Нужен компилятор C++14. Для сборки через CMake нужна версия 3.12 или новее. Из каталога проекта:

```powershell
cmake -S . -B build
cmake --build build --config Release
Push-Location build
ctest -C Release --output-on-failure
Pop-Location
```

Прямая сборка с GCC и проверка на небольшом примере:

```powershell
g++ -std=c++14 -O2 src/main.cpp src/fastwy.cpp -o fastwy.exe
.\fastwy.exe data/sample_item.csv data/sample_expression_over1.csv --exact
.\fastwy.exe data/sample_item.csv data/sample_expression_over1.csv 1000 42
```

Вторая команда перебирает все размещения меток при фиксированном числе положительных объектов. Режим ограничен 20 объектами и предназначен для проверки. Третья команда использует 1 000 случайных перестановок и seed 42. В случайном режиме допускается от 1 до 10 000 перестановок. Для сравнения между реализациями передайте те же метки:

```powershell
.\fastwy.exe items.csv labels.csv --permutation-file permutations.csv
```

## Форматы

Первый CSV содержит заголовок, идентификатор объекта и столбцы бинарных признаков. Второй CSV содержит заголовок и два столбца: идентификатор и бинарная метка. Идентификаторы уникальны и идут в одном порядке в обоих файлах. В выборке присутствуют оба класса. Поддерживается CSV с запятыми, без кавычек, пропусков и пустых строк. Файл перестановок без заголовка. Каждая строка содержит N бинарных меток в порядке объектов и сохраняет исходное число единиц.

Вывод — TSV. Строки метаданных содержат α, число перестановок, скорректированный порог для исходных p-значений и количество найденных наборов. Для каждого набора программа выводит поддержку, число положительных объектов, исходное p и перестановочную долю minP ≤ p. Порог 0 означает отсутствие допустимого положительного порога.

## Как работает прототип

Майнер перечисляет замкнутые наборы с заданным диапазоном поддержек. У наборов с одинаковым покрытием совпадает статистика при любой перестановке меток. Их представляет один замкнутый набор. Интерфейс Miner отделяет перечисление от статистического ядра.

Ядро просматривает наборы по убывающим диапазонам поддержки. Для каждой перестановки хранится свой минимум. Ниже числа положительных объектов граница минимального достижимого p монотонна по поддержке. Перестановка выходит из дальнейшего поиска, когда текущий минимум уже нельзя улучшить. Гипергеометрические хвосты вычисляются в логарифмической шкале и кэшируются по поддержке.

Из отсортированных минимумов берётся наибольшее наблюдавшееся значение, для которого не более floor(B/20) минимумов лежат на пороге или ниже. Если совпадающие минимумы пересекают эту границу, порог отступает перед всей группой. Поэтому на пограничных примерах правило может отличаться от авторского кода. Программа применяет порог к исходным p-значениям.

## Эталон

Файлы в data взяты из [авторского репозитория LAMP](https://github.com/a-terada/lamp/tree/master/sample). На примере 15 × 4 полный перебор 6 435 размещений даёт порог 57/6435 и набор TF1,TF2,TF3. Поддержка 5, все пять объектов положительные. Исходное p равно 45/6435, скорректированная доля равна 54/6435. Ожидаемый результат сохранён в tests/toy_expected.tsv.

## Эксперименты

Протокол, входы и результаты по номерам опытов входят в учебный архив задания 1.5.

Сырые наборы для подготовки UCI можно получить из первичных источников:

- [Mushroom](https://archive.ics.uci.edu/dataset/73/mushroom), файл agaricus-lepiota.data.
- [Tic-Tac-Toe Endgame](https://archive.ics.uci.edu/dataset/101/tic+tac+toe+endgame), файл tic-tac-toe.data.

Поместите оба файла в data/uci/raw и выполните python scripts/prepare_uci.py.
Для сверки с авторским кодом используются Python 3.12 и GCC. Исходный эталон — [LAMP, коммит 4bda274](https://github.com/a-terada/lamp/tree/4bda274138d12c7ea39b2a848672a10247f32f0a). Для проверок Windows предусмотрены scripts/prepare_reference.py, scripts/run_reference.py и scripts/measure_windows.py.

## Проверка сборки и дополнительные опыты

На Windows с GCC выполнить из корня проекта:

    ./scripts/check_build.ps1

Скрипт компилирует C++14, сверяет полный вывод игрушечного примера и печатает сведения о машине и компиляторе. Для проверки глобальной нулевой гипотезы:

    python scripts/check_null_fwer.py build/fastwy-check.exe experiments/14-null-fwer

Матрицы и протоколы исторических входов входят в учебный архив. Скрипты check_null_fwer.py, benchmark_matched_yeast.py, timed_fastwy.cpp и lcm_eval.cpp воспроизводят проверки и замеры опытов 13–15.

## Публичные протоколы и точное воспроизведение

[Машинно-читаемый комплект опытов](https://github.com/KoWalevDV/FastWY/releases/tag/experiments-v4) содержит подготовленные CSV, общие перестановки, TSV, measurements.csv, comparison.json и закреплённый архив исходников LAMP. После распаковки в корень клона:

    python scripts/verify_experiment_bundle.py .
    python tests/exhaustive_oracle.py ./fastwy.exe

В REPRODUCE.md приведены команды повторения конкретных численных результатов. scripts/fetch_historical_inputs.py независимо извлекает биологические входы из закреплённых Git-объектов и проверяет SHA-256.

Для эталона при ограниченной памяти доступен дополнительный режим хранения покрытий на диске:

    python scripts/replay_reference.py build/reference/lamp-master inputs permutations.csv author.log --disk-cache D:/FastWY-cache

Он заменяет список покрытий на последовательность в файлах, сохраняя статистические функции и порядок просмотра автора. Проверка на 1000 общих перестановках дрожжей сравнивает все minP, порог и находки. Команда python tests/test_reference_storage.py проверяет повторное чтение и добавление записей. Режим --accelerate выбирается отдельно.

Правило порога C++ выбирает максимум по наблюдавшимся minP с эмпирической долей ≤0,05. В граничном случае совпадений у первого ранга авторский adjustedThreshold может вернуть порог с долей выше 0,05. Эти случаи отдельно зафиксированы в опыте 18.

## Автоматические проверки

При наличии Python 3 CTest запускает четыре проверки: точный игрушечный вывод, независимый перебор 25 малых матриц, дисковую последовательность эталона и C++-модули. Без Python доступны игрушечный тест и C++-модули.

    cmake -S . -B build -G "MinGW Makefiles"
    cmake --build build
    ctest --test-dir build --output-on-failure

У MinGW 6.3.0 сборка Makefiles из пути с кириллицей может завершаться ошибкой поиска исходников. Для этого компилятора CMake/CTest проверен из копии в D:/FastWY-1.5/ctest-source-v2. Прямая команда g++ из каталога проекта также проверена.

Для длительных опытов измеритель поддерживает дополнительный контроль сна системы:

    python scripts/measure_windows.py --active-clock output.tsv error.log ./fastwy.exe items.csv labels.csv 1000 42

В JSON сохраняются прежнее полное elapsed_seconds, active_elapsed_seconds через QueryUnbiasedInterruptTime (без сна/гибернации), cpu_tree_seconds и peak_tree_commit_bytes. Старые вызовы и поля остаются совместимыми. Документация счётчиков: https://learn.microsoft.com/en-us/windows/win32/api/realtimeapiset/nf-realtimeapiset-queryunbiasedinterrupttime и https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information .

Опция --progress печатает номер текущей перестановки в stderr с немедленным сбросом буфера. Для длительного дискового прогона можно просматривать этот журнал отдельно.

## Полная сверка при дисковом хранении

Для GSE6462 выполнена авторская процедура на 1 000 общих перестановок с дисковым кэшем и счётчиком меток в C++. Все 17 находок, порог, поддержки, числа положительных и исходные p совпали с C++-прототипом. Четыре скорректированные доли отличаются согласно исходному adjustPval. Протоколы, сравнение и сырые выходы входят в опыт 21 открытого комплекта.

Исходная функция Fisher, границы поддержек, правила остановки и порога автора сохраняются. Дисковый счётчик получает каждое новое p через callback исходной Python-функции. Дополнительные проверки сравнивают все minP, поддержки остановки, числа кандидатов и счётчики новых p на 1 000 перестановок дрожжей и 20 перестановках GSE6462.

Сборка и запуск описаны в scripts/REFERENCE_DISK.md. Готовая Windows x64 DLL входит в открытый комплект в tools/reference_scan.dll. Её разрядность соответствует Python x64. Основной FastWY использует стандартную библиотеку C++14.
